## Purpose and exact mathematical question

Reproduce the three-dimensional Cohn–Elkies control with a fine grid and a
certified-sign run, and confirm the two-sided bracket

```
Li 2024 floor  <=  CE LP optimum (d=3)  <=  CE03 published value
0.770657           (what we compute)        0.779747          [occupied-volume density]
```

The VM run (`K = 31`, grid 1200) already gives `0.7797024`, i.e. `0.006%` below CE03 and
`1.17%` above Li's floor. The local run should (a) refine the grid until the reported value
stabilises, and (b) attempt an *interval* certification of the two sign conditions, which is
the only way this control becomes more than numerical evidence.

## Commands

```bash
# (1) fixtures, ~5 s, must all pass
cd KeplerConjecture/Computation && python3 k15conv.py && python3 fixtures.py

# (2) fine-grid control, ~3-6 min, single core, < 2 GB
python3 ce3_baseline.py --degree 41 --grid 4000 --r0 1.0 --out out/K41_g4000.json
python3 ce3_baseline.py --degree 31 --grid 4000 --r0 1.0 --out out/K31_g4000.json

# (3) the sharp-threshold variant (r0 = 2^(1/6), the value that would be needed
#     if a certificate with f(0) = fhat(0) were being sought), ~3-6 min
python3 ce3_baseline.py --degree 41 --grid 4000 --r0 1.122462048309373 --out out/K41_r0sharp.json
```

Dependencies: `python3`, `numpy`, `scipy` (HiGHS via `scipy.optimize.linprog`), `mpmath`.
No Lean, no compiled extensions. The VM used numpy 2.5.3 / scipy 1.18.1; any recent pair
should agree to the printed digits, and a disagreement of more than `1e-6` in `Delta` is a
finding to report rather than a failure.

## Success criteria

1. `fixtures.py`: all five fixtures pass, and F5 (`Poisson on FCC`) agrees to `< 1e-20`.
2. `Delta(K=41, grid 4000)` is within `1e-5` of the VM value `0.7797024` and still
   `<= 0.779747` (CE03) and `>= 0.770657` (Li). **If it exceeds `0.779747`, that is a
   finding: it would mean the family is worse than CE03's construction at this degree.**
3. Diagnostics reported: `max f` on `[1, 12]`, `min fhat` on `[0, 12]`, and their locations;
   the trend of both as `grid` doubles (they should shrink, confirming they are tangency
   artefacts rather than errors).
4. The `r0 = 2^(1/6)` run's value recorded, whatever it is, with its gap to Kepler.

**Correction (applies to the `r0 = 2^(1/6)` run below).** An earlier revision of
`ce3_baseline.py` omitted the `r0^3` factor from the density conversion, so the `r0`
variant would have been wrong. The CE Theorem 3.2 form is
`rho <= r0^n f(0)/fhat(0)` with `n = 3`; the sphere volume scales as `r0^3`. Fixed, and
the JSON now records `r0_scale_factor`. Re-run the `r0` variant only from the fixed code.

## Certification status

Exploratory floating point. `TESTED_FINITE` before and after the run. To upgrade any value
to a certificate, a further request must add interval arithmetic over a compact box plus an
analytic tail bound; the Gaussian decay `e^{-pi r^2}` makes the tail routine, and the
near-tangency points at `r = 1.64`, `s = 1.30` are where the interval work must be
concentrated. That is request `K15-COMPUTE-003` and is **not** part of this one.
