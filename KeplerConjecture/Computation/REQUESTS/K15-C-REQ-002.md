## Purpose

Reproduce the certified bounds in `CERTIFIER.md` §4 and extend the search. The
mathematical question is narrow: **how far does the indicated degree climb go before the
certified value stops improving?** The K=21 value `0.78010544` is +5.351% above Kepler; the
CE LP optimum is `0.779747` (+5.303%), so at most `0.05%` of headroom remains in this
family. The run establishes where the plateau is, and gives a reproducible certified
number for the project record.

## Commands (all light: no SDP, no Lean)

```bash
cd KeplerConjecture/Computation
python3 exactcert.py                      # smoke tests, ~2 s
for K in 9 11 13 15 17 19 21 23 25; do
  python3 gen_candidate.py --degree $K --npts 320 --Tmax 80 --out out/certificate_K$K.json
done
```

Each degree takes about 1–3 s; the whole loop under a minute. A wider sweep, if wanted:

```bash
for K in $(seq 21 2 41); do
  for T in 60 80 120; do
    python3 gen_candidate.py --degree $K --npts 400 --Tmax $T \
      --out out/sweep_K${K}_T${T}.json
  done
done
```

Dependencies: `python3`, `numpy`, `scipy` (HiGHS), `fractions` (stdlib). The checker
itself needs **only** the standard library — `exactcert.py` imports nothing outside it.

Resources: < 1 core, < 1 GB, < 5 minutes for the wide sweep.

## Success criteria

1. `exactcert.py` smoke tests behave as documented (both trivial `c` rejected).
2. Reproduce `K = 21`: certified `Delta <= 0.78010544` to all printed digits.
3. Report the certified value and the float LP value separately for every degree, and the
   rounding loss between them.
4. Identify the plateau degree: the smallest `K` beyond which the certified value no
   longer improves by more than `1e-6`.
5. **Any certified value below `0.779747` would be a finding** — it would contradict
   CE03's rigorous upper bound on the LP optimum, and would therefore indicate a bug in
   the checker, not a breakthrough. Treat it as such and report it immediately.

## Certification status

The bounds are `PROVED` conditional on the cited Cohn–Elkies theorem. Verification is
exact: Sturm sequences over `Q` plus Yun squarefree decomposition, with `pi` enclosed by
rationals in the safe direction. Nothing in the verification is floating point. The
search that *finds* candidates is heuristic and is irrelevant to validity.
