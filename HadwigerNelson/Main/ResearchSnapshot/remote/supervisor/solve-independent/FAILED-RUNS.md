## Failed runs, with cause

1. **`RUP FAILURE at step 26154` (twice, same step).** Cause: the checker (i) added proof clauses whose
   watched literals were already false at level 0, breaking the watch invariant, and (ii) *enqueued
   unit clauses derived mid-proof but never propagated them*, so their consequences were never
   derived. Defect (ii) was the real one. Localised by a naive independent propagation in Python on
   that single step, which showed the step **was** RUP — i.e. the proof was fine and my checker was
   wrong. Both fixed; the shipped `rup.c` verifies all 42109 steps in ~20 s.
2. **`p19_shrink.py` timeout.** Greedy core minimisation: each removal attempt rebuilds the CNF and
   starts a solver. Exceeded the 60 s single-process cap with no output.
3. **`k = 7` DRUP generation timeout.** Refuting 7 colours on 73 vertices is substantially harder than
   6; generation exceeded the cap, so no certificate exists for `chi = 8`. **Not** retried, and per
   supervisor instruction no further 7-UNSAT or core work is done.
4. **`patch19.py` first structural bugs (earlier block).** None in the final version, but recorded
   because the same code family produced them once: a lower-triangular Hermite normal form in the
   sublattice enumeration was incomplete (missed 6 of 8 index-7 sublattices, wrongly reporting 8
   instead of 7 at `a = 2/5`), and an inverted critical-point test for the subintervals of `a`.
5. **Earlier over-claims, retracted in place** (see the banners): "the forced set is exactly
   `{1,3,4}` on `[1/sqrt13,1/2)`" (false below `1/sqrt7`); "a six-colouring must be cell-free"
   (cannot follow from a restricted family); "the `K_7` route is closed on `[0.12204, 0.27735)`"
   (it closes only the *clique* route, below diameter `0.24407`); "every 6-subset of the 16 cosets
   contains an edge ⇒ chromatic obstruction" (true but insufficient; the `K_16` clique is the argument).
